# Vault conventions

`brain-mcp` reads any folder of Markdown files, but it is designed around a way of keeping notes that works well with AI agents, often called an **LLM wiki**: people bring sources and facts, the agent summarizes, links and keeps things tidy, and the vault becomes shared memory for both.

## Every note has a type and a summary

```yaml
---
type: project
summary: Plan and risks for Harbor's public launch in November 2026
---
```

The summary is one specific sentence. It is what `vault_index` and the generated index show, so it decides whether an agent opens the note at all. "Plan and risks for the launch in November" helps; "Launch notes" does not.

`type` is a small vocabulary you choose (`project`, `person`, `concept`, `decision`, `diary`, ...). It lets agents filter, for example "list every decision".

## Read the index first

The index (`index.md` by default) is generated by `index_build` from the summaries. Agents start with `vault_index` or `note_search`, pick the few notes that matter and read only those, often a single section. This keeps context small and answers grounded in the right notes.

## Link everything

People, projects and concepts are linked with wikilinks (`[[Maya Chen]]`). Links are how an agent moves from a decision to the people involved, and backlinks show where something is referenced. `vault_lint` reports broken and ambiguous links and orphan notes.

## A daily note for decisions

The daily note (`diary/2026/2026-09-29.md`) gets one line per event worth keeping: a decision, a delivery, a new fact. Sections keep it scannable (`Product`, `Engineering`, `Decisions`). The day's summary is written when the day closes, so an open day is not reported as missing one.

Agents log with `diary_add` during the work, not at the end, so nothing depends on remembering.

## An inbox for new notes

Agents create new notes in `inbox/` and a person files them later. Keeping agent writes in a few folders makes them easy to review.

## Some things never go in a note

Passwords, tokens, document numbers and similar data stay out of the vault. Keep them in a password manager or in a folder that the vault blocks, and let the note say only that the document exists. `brain-mcp` refuses writes that look like secrets and `vault_lint` flags existing ones.

## Instructions for agents

A short `AGENTS.md` (or `CLAUDE.md`) at the root tells agents how this vault works. The [example vault](../examples/vault/AGENTS.md) has one you can adapt.

## Adopting it in an existing vault

1. Add `brain.config.yaml` with your `blocked` folders first.
2. Start the server with `--read-only` and run `vault_lint` to see what is missing.
3. Add `type` and `summary` to the notes you use most, then run `index_build`.
4. Allow writes to `diary/**` and `inbox/**` when you are comfortable.
